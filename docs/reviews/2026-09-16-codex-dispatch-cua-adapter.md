# ChatGPT 调度工具适配与失败恢复整改

日期：2026-09-16。最新状态：同一 IAB 的公开 DOM 路径已完成无附件“6 Pro”单次发送和同页回收。标准 CUA 自动 AX 读取仍失败；底层延迟未定位。下文保留首轮结果，最新实测与纠正在末节。

## 问题与改动

旧 Skill 把 `browser:control-in-app-browser` 设为必需条件，并在附件流程中直接使用旧
Browser 的 `markHandoff` 等方法。当前宿主公开提供 CUA 的 IAB 入口；同一表面更换
控制器不应单凭旧名字缺失而停下或重复请求业务授权。

本次保留“材料完整、精确档位、一次提交、同页回收”的目标，修改控制器选择和失败交付：

- 使用当前同一 IAB 的公开契约，CUA 首次／reset 后单独初始化，读取文档再操作。
- 旧控制器仍可使用其当前文档；专属方法不跨控制器移植。无受支持入口立即交付材料。
- 一轮最小只读恢复无进展就停止，区分连接未证实、页面状态过期、发送未知。
- 用户手动接管时给完整材料主入口、附件用途与可复制控制语，停止自动发送。
- 附件按需加载与核对；历史应用版本不作当前保证，选择器超时不直接归因于产品限制。
- 同步人类 README、根入口及相关旧场景，新增 CUA、超时与人工接管场景。

没有建立通用浏览器框架或重试队列。账号与外发边界、Pro 精确选择、不干预推理、
冻结材料变更阻断、只发送模式、完整留存与本地核验规则保留。

   无 API 文档或表面状态。

4. 返回同样错误，工具报告耗时 30.0460 秒，仍无文档或页面状态，停止探测。

这两次调用不涉及完整 DOM、文件上传、模型选择或发送。可以排除“本次把多个 API 合并
进初始化”这种调用方式错误；不能据此定位桥接、宿主进程、权限、连接或其他实现原因。
没有读取 Cookie、认证数据、Browser Profile 或私有接口。没有拉长 timeout、重建
对话、循环 reset 或重启用户应用。

该结果与此前交接中的创建标签页超时／只读恢复超时相符，但不是对那次根因的证明。
日志 SDK 的 Pro 审阅由用户手动推进，本次没有发送、重发或接管。

后续复验须有新的宿主恢复信号或用户要求：先单次初始化取得文档，再定位同一 IAB

## 2026-09-22 选模控件定位恢复

跨任务实际使用已读取新版 Skill 并恢复同 IAB，但在“极高 → Pro”的 slider 角色定位连续超时。此前验证从已选好 Pro 的页面开始，未覆盖这一步；不能据文本／附件发送成功宣称完整选模能力。

独立空白 IAB 页复现：菜单局部 innerText 成功；`getByRole("slider").evaluate(...)` 返回 selector deadline exceeded。公开只读 DOM 查询取得唯一可见滑块（28 × 28），同时有 `role="slider"`、`aria-hidden="true"`、`data-orientation="horizontal"`。角色选择器默认排除 ARIA 隐藏元素，见 [Playwright 文档](https://playwright.dev/docs/api/class-page#page-get-by-role)。这是本次定位失败的原因，不是所有 CUA 超时的根因。

根据实际 DOM 使用 `locator('span[role="slider"][data-orientation="horizontal"]').press(...)`，ArrowLeft 将 Pro 切至极高，ArrowRight 切回 Pro。每次独立读取菜单，分别回显“极高，第 4 项，共 5 项”和“Pro，第 5 项，共 5 项”。按键耗时 30.18／34.87 秒，菜单读取约 30 秒，工具时限 60 秒。没有上传、输入或发送业务请求，没有修改页面 DOM 或使用私有接口；诊断页已关闭。选择器只记录当日证据，不要求未来照搬。
