# IAB 人工上传与排障

仅在 `codex-chatgpt-dispatch` 本轮包含文件附件，或出现 Browser 上传、标签页恢复相关
异常时读取。本文件记录高漂移的产品事实和稳定处理原则；正常无附件调度不需要加载。

## 当前基线

截至 2026-09-01：

- OpenAI 官方 Browser 文档明确说明，ChatGPT 不能在内置 Browser 中自动执行文件
  上传：<https://learn.chatgpt.com/docs/browser>。
- 2026-07-31 的本机历史证据显示，IAB Browser 插件 `26.727.40816` 曾能通过
  `filechooser` 和 `setFiles()` 把文件加入 ChatGPT 输入框。
- 本机 ChatGPT 桌面应用与 Browser 插件当前均为 `26.825.51511`（build `7377`）。本轮只读
  预检确认官方限制仍存在，未重复真实上传探测。
- 当前打包的通用 Browser API 和文件上传说明仍可能暴露 `waitForEvent("filechooser")`
  与 `setFiles()`。接口存在不等于 IAB 后端支持，不能据此覆盖官方边界和真实观测。

可以确认的是“当前官方 IAB 边界不允许自动上传”。现有证据不能区分这是有意收紧还是
产品回归，也不能定位到具体提交。在本次记录的版本与官方边界下，有附件就使用一次
人工上传检查点；以后每次附件任务先按下节静默预检。

## 附件任务的静默能力预检

不做定时轮询。每次真正触发带附件的调度时，在打开或接管目标对话前完成一次低成本、
只读预检；当前边界没有变化时不向用户播报。

按以下证据顺序判断：

1. **官方 Browser 能力文档**是当前产品边界的第一证据。读取正文，确认是否仍明确说明
   IAB 不能自动上传，不以搜索摘要或本地缓存替代。
2. **官方 ChatGPT & Codex changelog**只用于发现恢复信号。更新说明提到文件上传时，
   还要与能力文档交叉核对；单条 changelog 不直接等于当前表面已恢复。
3. **本机版本**只记录运行环境是否漂移。macOS 应读取
   `/Applications/ChatGPT.app/Contents/Info.plist` 中的 `CFBundleShortVersionString` 和
   `CFBundleVersion`，并查看 `~/.codex/plugins/cache/openai-bundled/browser/` 下当前
   Browser 插件版本目录。版本变化本身不证明能力恢复。
4. 通用 Browser API、普通 Playwright、Chrome 扩展、历史成功记录或旧版 Skill 文档
   都不是当前 IAB 自动上传可用的充分证据。

官方入口：

- Browser 能力文档：<https://learn.chatgpt.com/docs/browser>
- ChatGPT & Codex changelog：<https://learn.chatgpt.com/docs/changelog>

| 预检结果 | 用户可见动作 | 本轮路径 |
| --- | --- | --- |
| 官方文档仍明确不支持 | 无；不为普通版本变化打扰用户 | 人工上传，不探测 |
| 只有应用或插件版本变化 | 无 | 人工上传，不探测 |
| 官方资料不可访问或表述不清 | 无；未知不视为恢复 | 人工上传，不探测 |
| 官方明确新增支持或删除原限制 | 提示一次“发现恢复信号”，请求安全探测授权 | 授权前保持人工路径 |
| 可靠的 `fileUpload` 能力标志出现 | 同上 | 授权前保持人工路径 |
| changelog 与能力文档实质冲突 | 同上，并说明证据冲突 | 授权前保持人工路径 |

因此，用户会在**下一次实际使用本 Skill 调度附件**时自动知道是否出现恢复信号；这不
提供后台通知、定时监控或对 ChatGPT 产品更新的持续订阅。

## 一次性安全探测

只有出现上述恢复信号，或用户明确要求复验时，才请求一次授权。未获得授权不得通过
真实点击、`filechooser`、`setFiles()` 或私有接口试探。

获得授权后：

1. 创建或选用一个临时、无敏感内容的小型 `.txt` 文件；不得使用真实项目材料。
2. 在目标账号的空白、尚未发送的输入框中尝试挂载该文件。
3. 同时捕获文件选择器等待和点击等所有异步分支，避免未处理拒绝重置运行内核。
4. 只以页面真实显示测试附件作为成功证据；随后立即移除附件，不输入请求、不发送。
5. 成功只证明当前应用版本、Browser 插件版本和当前 IAB 表面可用。本轮可以再按正常
   外发与发送授权自动上传真实附件；经用户授权后，在 Skill 源仓回写本文件的验证
   日期、应用版本、插件版本和适用表面，再同步安装副本。
6. 失败时说明一次结果，停止探测并回到人工上传；同一版本不连续尝试其他入口。

不能从测试文件已加入页面外推文件大小、格式、数量限制或上传后的解析质量；真实附件
仍需按提交清单核对文件名、数量与页面错误。以后只有本机版本与已记录成功版本一致、
官方文档仍支持且当前页面能力没有反证时，才可复用这条成功基线；任一版本变化后重新
回到静默预检，不能沿用旧结论。

## 正常人工上传检查点

目标是让用户只承担系统目前不能完成的选文件动作，其余判断和页面操作仍由 Skill
完成。

1. 在本地形成唯一冻结集合，检查文件存在、可读、用途明确且没有确定性外发风险。
2. 附件原本位于同一目录且文件名唯一时，直接使用该目录。跨目录或存在同名时，在安全的
   临时位置生成一个“任务主题-upload”发送目录，复制冻结版本；同名文件使用有意义的任务名或
   短用途前缀区分，不使用括号编号当版本号。
3. 使用 `shasum -a 256` 记录源文件和发送副本的 SHA-256。冻结或上传后任一哈希变化，
   页面附件立即失效，必须重新冻结、上传和核对。
4. Browser 打开或恢复目标 ChatGPT 对话，核对账号并选好用户指定档位。
5. 一次展示完整上传卡：总数、文件名、用途、SHA-256、发送目录和绝对路径。当前聊天支持
   本地文件链接时，优先输出 `[文件名](/absolute/path)` 和 `[打开上传目录](/absolute/directory)`；
   不支持时再退回绝对路径代码块。
6. 结束当前轮次前调用 `tab.markHandoff()`，让目标标签页跨轮保留。请用户只上传附件、
   不要发送，完成后回复“已上传”。
7. 下一轮恢复同一标签页，从页面核对附件数量、所在对话和身份。页面把 `name.ext` 显示为
   `name (N).ext` 时，先视为平台展示重命名；当冻结集合中的原始名唯一，且数量、会话、
   上传顺序和页面可见文件类型都一致时，按同一附件继续，不因括号编号改稿或重传。
   仍无法唯一对应时才停止。
8. 已有发送授权仍然有效，不为形式完整重复确认；输入控制语并只发送一次。

macOS 文件选择器中可以按 `⌘⇧G` 粘贴发送目录；文件已集中时应让用户一次多选。

人工上传是当前受支持的协作检查点，完成后调度状态记录为“人工辅助调度成功”。只有
无人工核心步骤的完整链路才记录为“自动调度成功”。

## 已观察到的失败及分类

### 通用选择器命中多个文件输入

ChatGPT 页面可能同时存在普通文件、照片和相机输入。直接使用
`input[type="file"]` 会命中多个元素并产生 strict-mode 错误。

这是定位错误，不代表产品支持或不支持上传。当前 IAB 不应继续换选择器重试；直接
进入人工上传检查点。

### 文件选择器等待超时

即使定位到精确普通文件输入或可见的“从电脑上传”菜单，仍可能出现：

```text
Timed out after 3000ms waiting for file chooser.
```

在当前 IAB 基线下，把它分类为能力不支持。捕获错误并停止，不增加等待时长，不连续
切换多个上传入口，也不转向私有上传接口。

### 未处理的异步拒绝导致运行内核重置

先创建文件选择器等待 Promise、随后点击失败或等待超时，如果没有同时捕获两条异步
路径，可能产生未处理拒绝并重置 Browser 运行内核。

这是 Agent 执行错误，会丢失临时句柄，但不证明页面或请求状态。重新连接后先只读
检查原会话，不声明上传成功或失败，不重新发送。

### `Unknown tab`

Agent 创建的 IAB 标签页默认可能在轮次结束时关闭。暂停让用户上传前没有调用
`tab.markHandoff()`，下一轮就可能得到 `Unknown tab`。

这是标签页生命周期错误。恢复原会话 URL 后先检查是否已经上传或发送；不要因为句柄
失效新建对话并重复提交。跨轮仍需继续保留时，每轮结束前重新调用 `markHandoff()`。

## 排障决策表

| 现象 | 判断 | 动作 |
| --- | --- | --- |
| 预检确认官方仍不支持，附件尚未上传 | 当前产品限制 | 直接展示上传卡，不做自动上传探测 |
| 用户上传后附件缺少或多出 | 页面状态不符合提交清单 | 一次列出差异，停止发送 |
| 页面显示 `name (N).ext` | 可能是平台展示重命名 | 先用冻结集合、数量、会话、顺序和类型核对；能唯一对应就继续 |
| 冻结后源文件或发送副本 SHA-256 变化 | 页面附件已失效 | 停止发送，重新冻结、上传和核对 |
| 上传后页面出现文件错误 | 文件或页面拒绝 | 保留原文件，说明页面错误；允许用户修正一次 |
| `filechooser` 超时 | 当前 IAB 不支持 | 捕获并停止，转人工上传 |
| strict-mode 多元素 | 定位不唯一 | 不换选择器试错，转人工上传 |
| Browser 内核重置 | 异步错误未被处理 | 重连并只读恢复原页面 |
| `Unknown tab` | 未保留标签页或句柄过期 | 恢复原 URL，检查是否已发送，再调用 `markHandoff()` |
| 用户误触发送 | 不可逆动作已发生 | 核对现有提交并等待，绝不再发一次 |

## 可选的未来路径

官方 Chrome 扩展在开启“Allow access to file URLs”后仍支持文件上传：
<https://learn.chatgpt.com/docs/chrome-extension>。当前 Skill 不自动切换 Chrome，避免在
没有完成同一会话、侧栏展示和账号边界验证前增加第二条主链。用户明确选择并完成独立
验证后，才把 Chrome 作为新的正式适配器。
