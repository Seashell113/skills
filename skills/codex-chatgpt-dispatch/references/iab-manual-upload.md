# IAB 人工上传与排障

仅在 `codex-chatgpt-dispatch` 本轮包含文件附件，或出现 Browser 上传、标签页恢复相关
异常时读取。本文件记录高漂移的产品事实和稳定处理原则；正常无附件调度不需要加载。

## 当前基线

截至 2026-08-18：

- OpenAI 官方 Browser 文档明确说明，ChatGPT 不能在内置 Browser 中自动执行文件
  上传：<https://learn.chatgpt.com/docs/browser>。
- 2026-07-31 的本机历史证据显示，IAB Browser 插件 `26.727.40816` 曾能通过
  `filechooser` 和 `setFiles()` 把文件加入 ChatGPT 输入框。
- ChatGPT 桌面应用和 Browser 插件更新到 `26.810.52044`（build `6662`）后，精确
  点击普通文件输入或可见上传菜单都无法产生自动化可用的文件选择器事件。
- 当前打包的通用 Browser API 和文件上传说明仍可能暴露 `waitForEvent("filechooser")`
  与 `setFiles()`。接口存在不等于 IAB 后端支持，不能据此覆盖官方边界和真实观测。

可以确认的是“当前 IAB 自动上传不可用”。现有证据不能区分这是有意收紧还是产品
回归，也不能定位到具体提交。处理上不依赖这个归因：有附件就使用一次人工上传检查点。

## 正常人工上传检查点

目标是让用户只承担系统目前不能完成的选文件动作，其余判断和页面操作仍由 Skill
完成。

1. 在本地冻结唯一附件集合，检查文件存在、可读、用途明确且没有确定性外发风险。
2. Browser 打开或恢复目标 ChatGPT 对话，核对账号并选好用户指定档位。
3. 展示上传卡：总数、按父目录分组的文件名、用途、绝对目录和绝对文件路径。
4. 结束当前轮次前调用 `tab.markHandoff()`，让目标标签页跨轮保留。
5. 请用户只上传附件、不要发送，并在完成后回复“已上传”。
6. 下一轮恢复同一标签页，从页面核对附件名、数量、目标档位和请求尚未发送。
7. 已有发送授权仍然有效，不为形式完整重复确认；输入控制语并只发送一次。

macOS 文件选择器中可以按 `⌘⇧G` 粘贴上传目录。附件在同一目录时，应让用户一次
多选；附件跨目录时按目录分组，避免在一张长清单中来回寻找。

人工上传是当前受支持的协作检查点，完成后调度状态记录为“人工辅助调度成功”。只有
无人工核心步骤的完整链路才记录为“自动调度成功”。

## 已观察到的失败及分类

### 通用选择器命中多个文件输入

ChatGPT 页面可能同时存在普通文件、照片和相机输入。直接使用
`input[type="file"]` 会命中多个元素并产生 strict-mode 错误。

这是定位错误，不代表产品支持或不支持上传。当前 IAB 不应继续换选择器重试；直接
进入人工上传检查点。

### 文件选择器等待超时

即使定位到精确普通文件输入或可见的“从电脑上传”菜单，仍可能出现：

```text
Timed out after 3000ms waiting for file chooser.
```

在当前 IAB 基线下，把它分类为能力不支持。捕获错误并停止，不增加等待时长，不连续
切换多个上传入口，也不转向私有上传接口。

### 未处理的异步拒绝导致运行内核重置

先创建文件选择器等待 Promise、随后点击失败或等待超时，如果没有同时捕获两条异步
路径，可能产生未处理拒绝并重置 Browser 运行内核。

这是 Agent 执行错误，会丢失临时句柄，但不证明页面或请求状态。重新连接后先只读
检查原会话，不声明上传成功或失败，不重新发送。

### `Unknown tab`

Agent 创建的 IAB 标签页默认可能在轮次结束时关闭。暂停让用户上传前没有调用
`tab.markHandoff()`，下一轮就可能得到 `Unknown tab`。

这是标签页生命周期错误。恢复原会话 URL 后先检查是否已经上传或发送；不要因为句柄
失效新建对话并重复提交。跨轮仍需继续保留时，每轮结束前重新标记 handoff。

## 排障决策表

| 现象 | 判断 | 动作 |
| --- | --- | --- |
| IAB 有附件但尚未尝试上传 | 当前产品限制 | 直接展示上传卡，不做自动上传探测 |
| 用户上传后附件缺少或多出 | 页面状态不符合提交清单 | 一次列出差异，停止发送 |
| 文件名重复，无法唯一核对 | 附件身份不清 | 使用路径与用途重新确认，必要时重命名本轮生成文件 |
| 上传后页面出现文件错误 | 文件或页面拒绝 | 保留原文件，说明页面错误；允许用户修正一次 |
| `filechooser` 超时 | 当前 IAB 不支持 | 捕获并停止，转人工上传 |
| strict-mode 多元素 | 定位不唯一 | 不换选择器试错，转人工上传 |
| Browser 内核重置 | 异步错误未被处理 | 重连并只读恢复原页面 |
| `Unknown tab` | 未保留标签页或句柄过期 | 恢复原 URL，检查是否已发送，再重新 handoff |
| 用户误触发送 | 不可逆动作已发生 | 核对现有提交并等待，绝不再发一次 |

## 何时重新验证自动上传

以下任一信号出现时，才建议用无敏感、可删除的小型文本文件复验：

- OpenAI 官方 Browser 文档重新明确支持 IAB 自动上传；
- ChatGPT 桌面应用或 Browser 插件升级，并在变更说明中提到文件上传；
- 当前 Browser 提供明确、可查询的 `fileUpload` 能力标志；
- 用户明确要求重新验证。

复验只验证“捕获文件选择器 → 加入测试文件 → 页面显示附件 → 删除附件”，不发送
测试请求，不使用真实项目材料。成功后仍应更新本文件的验证日期、版本和适用表面，
不能从 Chrome 扩展或普通 Playwright 的成功外推 IAB。

## 可选的未来路径

官方 Chrome 扩展在开启“Allow access to file URLs”后仍支持文件上传：
<https://learn.chatgpt.com/docs/chrome-extension>。当前 Skill 不自动切换 Chrome，避免在
没有完成同一会话、侧栏展示和账号边界验证前增加第二条主链。用户明确选择并完成独立
验证后，才把 Chrome 作为新的正式适配器。
