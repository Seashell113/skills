# IAB 附件能力与人工上传

仅在本轮需要文件附件或正在处理附件问题时读取。连接与页面读取故障统一见
[主流程第 5 节](../SKILL.md#5-通过内置-browser-和受支持的附件路径只提交一次)，
无附件时不加载本文件、不检查应用版本、不探测上传。

## 先核对当前能力

上传许可、控制器接口和同表面成功观测分别核对，任何一项都不能代替其余项。

1. 阅读当前控制器已返回的公开文档，确认它是否提供适用于 IAB 的上传操作。
   旧 Browser 对象的方法不能直接用于 CUA；通用 API 存在不等于 IAB 后端支持。
2. 读取适用的[官方 Browser 文档](https://learn.chatgpt.com/docs/browser)正文中的
   内置浏览器章节，核对产品限制；不要把同页的云端浏览器或普通 Chrome 当作 IAB。
3. 只有资料出现实质变化、需要复验或排障时，记录本次可确认的宿主／插件版本与日期。
   不硬编码应用名称、安装路径或插件目录；版本变化本身不证明能力恢复。

| 当前证据 | 处理 |
| --- | --- |
| 官方仍明确不支持自动上传 | 直接人工上传，不请求探测、不尝试文件入口 |
| 文档不可读、表面不匹配、仅有通用 API 或只有版本变化 | 能力未知，使用人工路径，不声称产品永久不支持 |
| 官方明确支持或原限制消失，当前 IAB 控制器也有公开适用接口 | 视为恢复信号；无本次适用成功证据时请求一次无敏感探测授权 |
| 官方与宿主能力实质冲突 | 告知冲突，保持人工路径；未消解限制前不自动上传 |
| 当前表面、契约和版本有可复用成功证据且无反证 | 按本轮已有外发与发送授权上传，再核对真实附件 |

不做后台轮询；普通版本更新不额外打扰用户。需要发现恢复信号时可定向查
[官方 changelog](https://learn.chatgpt.com/docs/changelog)，不每轮加载完整历史。

### 有日期的证据，不能当作永久保证

- **2026-09-16 官方正文核验**：Browser 页的 “Computer Use in the browser” 章节说明
  Codex 可通过 Computer Use 操作内置浏览器，并仍明确不支持自动文件上传。
  因此本次保持人工上传；未进行新的上传实测。
- **2026-09-01 历史核验**：旧记录中的应用／Browser 插件版本为 `26.825.51511`
  （build `7377`），当时官方限制仍存在。它不是本机当前版本。
- **2026-07-31 历史观测**：旧 IAB 插件 `26.727.40816` 曾用 `filechooser` 与
  `setFiles()` 挂载文件，只证明当时的特定环境，不用于当前 CUA 调用。

## 冻结材料与一次人工上传

1. 确认最小附件集合存在、可读且通过主流程的外发检查。记录文件名、用途、源路径、
   发送副本路径和 SHA-256。目录相同且文件名唯一时直接使用原目录；跨目录或同名时，
   在安全临时位置复制为一个任务发送目录，用任务名或用途前缀消除重名。
2. 按当前控制器文档准备同一 ChatGPT 页面，核对账号与用户指定档位。若连接失败，
   立即交付材料卡并说明页面尚未核验，不宣称已停在可上传状态。
3. 一次给全上传卡：文件总数、每个精确文件名、用途、SHA-256、发送目录和可点击的
   绝对路径链接。macOS 文件选择器可用 `⌘⇧G` 粘贴目录后一次多选。
4. 暂停前按当前控制器的生命周期文档保留原标签页和 URL。只有旧控制器明确提供
   `tab.markHandoff()` 时才调用；CUA 无该契约时不得调用，也不保证句柄跨轮有效。
   请用户只上传、不要发送，完成后回复“已上传”。用户选择自己发送时转主流程人工交付。
5. 恢复同一页面，核对对话、档位、附件数量和身份；重新计算源文件与发送副本哈希。
   任何源文件或副本变化都使页面旧附件失效，停止发送并重新冻结、上传、核对。
6. 页面把 `name.ext` 显示为 `name (N).ext` 时先视为展示重命名。冻结原名唯一且数量、
   对话、上传顺序、可见类型一致时可继续；仍不能唯一对应时停止，不因编号改稿重传。
7. 同一请求未发送且用户仍只承担上传时，沿用已有发送授权，不重复确认。用户已经发送
   或发送未知时先核对原对话，绝不再次发送；用户已改为手动推进时不恢复自动发送。

本流程成功记为“人工辅助调度成功”；用户手动承担其余核心步骤时记为“人工接管”。
单纯材料交付与真正调度成功分别记录。

## 一次授权探测

只有上文恢复信号成立或用户明确要求复验，且不违反当前产品／宿主限制时进行。
先准备临时无敏感小型 txt，说明目标 IAB 表面、一次挂载后移除、不发送的验收目标，
取得对应授权；已有授权范围清楚时不重复询问。

按当前控制器文档执行，仅用文档支持的上传方法。若该方法有等待和点击等异步分支，
同时捕获它们的成功与失败；不留下未处理拒绝。页面真实显示测试附件后移除，核对已移除，
不输入请求、不发送。记录实际控制器、可得版本、日期、表面与结果；未知字段保持未知。

成功仅证明该环境能挂载这个文件，不外推大小、格式、数量、解析质量。真实附件仍需
材料闭合、外发授权与页面核对。失败后不拉长等待、不切换入口、不循环测试；回到人工
路径。回写源仓或安装态另按对应任务授权，不能由探测成功自动扩大。

## 故障分类

| 现象 | 可以确认 | 下一步 |
| --- | --- | --- |
| 官方明确不支持 | 当前产品限制 | 人工上传 |
| 精确入口 `filechooser` 超时 | 此次未取得选择器，原因未定位 | 停止尝试；结合当前契约与官方边界选择人工路径 |
| strict-mode 多元素 | 当前定位不唯一 | 停止这次动作，按当前文档重新观察；不靠轮换入口试错 |
| 已有证据表明等待 Promise 未处理 | 执行方式有误 | 捕获所有异步分支，按主流程有界恢复；不据此推断页面发送状态 |
| 仅看到 kernel reset | 控制器运行状态丢失，根因未知 | 一轮只读恢复；不一概归因于 Promise 或上传 |
| `Unknown tab` | 句柄失效，原因待查 | 定位原 URL 和现有标签页，检查已上传／已发送状态；不新建替代对话 |
| 附件数量或身份不符、页面报错 | 当前材料未通过核对 | 集中列出差异，停止发送 |
| 冻结哈希变化 | 页面材料已失效 | 重新冻结、上传、核对 |
| 用户误触发送 | 可能已提交 | 核对现有请求，绝不重发 |

旧 Browser 曾要求 `markHandoff()` 防止跨轮关闭；这只是旧控制器的生命周期规则。
当前 `Unknown tab` 也可能来自句柄过期或页面关闭，不能单凭错误判定漏调旧 API。
