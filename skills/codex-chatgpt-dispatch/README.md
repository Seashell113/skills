# codex-chatgpt-dispatch

面向提供内置 Browser（IAB）的 Codex 桌面宿主。整理完整上下文，精确核对用户指定的
ChatGPT 网页档位，只提交一次，再按要求立即返回或同页等待、回收、本地核验。

一条文本能够承接任务时直接输入；需要结构化材料、较多附件索引、跨轮复用或用户明确
要求时才生成 handoff。附件单独判断，冻结最小发送集合与 SHA-256；当前自动上传限制
下提供集中的上传卡。工具故障时当轮交付可用材料和控制语，并明确发送状态。

## 调用示例

仅显式调用，普通评审和“要不要让 Pro 看看”不会自动调度：

```text
$codex-chatgpt-dispatch 先整理当前方案的 handoff，不要提交
$codex-chatgpt-dispatch 用页面当前可用的 Pro 深度评审并提交一次
$codex-chatgpt-dispatch 组织发送就行，不用等结果
$codex-chatgpt-dispatch 用新增证据在原对话继续讨论一轮
$codex-chatgpt-dispatch 完整留存这次对话
```

显式触发只授权加载与准备材料，发送须有当前任务授权。修改本 Skill 的请求不构成
任何评审请求的发送授权。

## 当前工具适配

优先复用已连接的同一 IAB 控制器。CUA 明确支持 `iab` 时按其公开契约使用；只有旧
`browser:control-in-app-browser` 时加载旧 Skill 并遵循它的当前文档。旧名字缺失
不会单独阻塞同一 IAB 路径，也不需要额外重复授权。

CUA 首次／reset 后只做一个适用入口调用，读取返回文档后再进行页面操作；不能把旧
`markHandoff`、`filechooser` 或 `setFiles` 方法复制过去。连接失败只做一轮最小只读
恢复，没有新状态就停止。保留原 URL、材料和“未发送／发送未知／已提交”状态，不重开、
不重发、不通过延长等待掩盖故障。

**能力声明与实测分开**：2026-09-16 的 CUA 初始化与只读恢复均约 30 秒超时，未得到
页面状态；本次整改不声称自动链路恢复。公开工具契约可支持适配设计，离线场景只能验证
执行决策。真实连接、选模、上传和同页提交回收分别验收。

## 流程与边界

1. 盘点必要事实、用户锁定约束、推断、分歧、未知项与输出要求，选择完整直接文本或 handoff。
2. 有附件才加载上传细则，核对当前宿主与官方边界，冻结最少文件；无附件不探测上传。
3. 核对原／新对话、账号、产品档位、模型、思考强度、材料和发送授权。Pro 首次未见时
   只对相关控件有界复查，不静默降档。
4. 必要时用户只上传，Agent 保留并恢复同页核对附件；材料哈希变化使旧附件失效。
5. 同一请求只提交一次。只发送模式确认页面接受后立即返回；其他模式同页被动等待，
   不点击“立即回答”或“停止回答”。
6. 已提交后页面恢复失败才使用原生 task 只读恢复；候选不唯一不猜测。
7. Codex 本地核验。明确要求完整留存时保存一份完整可见回复、材料身份与采纳结论记录。

用户改为手动时立即交付主材料入口与可复制提示词，停止自动发送。发送未知先核对原
对话；用户已发送时只核对现有提交。工具后来恢复也不会重新发送。

通用 Playwright、Chrome、API、私有接口或原生 task 不自动成为备用提交链。
当前原生 task 工具的 Codex 模型覆盖不等于 ChatGPT 网页 Pro 档位控制。更换提交表面
需要另行确认并完成同表面验证；不读取 Cookie、Browser Profile、凭据或认证存储。
材料外发不包含凭据、生产隐私等禁止项；组织政策或外发权限有实质不确定性时停止。

完整自动链、人工辅助上传、人工接管、材料已交付、发送未知、已提交但结果未回收分别
报告。工具描述、安装成功和离线评测都不替代真实自动调度验收。
