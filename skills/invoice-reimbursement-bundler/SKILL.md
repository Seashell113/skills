# invoice-reimbursement-bundler

本地发票 PDF 的报销打包助手。只做确定性文件操作：读取 PDF 文本、解析发票号、价税合计和购买方抬头，按规则组合，经用户确认后移动文件。不依赖 OCR，不调用外部服务。

## 触发与不触发

适合使用：

- "帮我统计一下这个目录的发票总额"
- "把这些发票凑成 3000 元报销"
- "按发票号查一下有没有重复"
- "检查这些发票的抬头是否一致"
- "把选中的发票移动到一个新文件夹"
- "从之前的报销目录和剩下的票重新拼一单"
- "/invoice-bundle" 或类似自然语言

不适合使用：

- 需要识别扫描件图片中的发票（只做文本提取，不做 OCR）
- 需要自动删除、清理旧目录或修改原始文件名
- 涉及增值税查验、真伪校验、税务申报等税务合规操作

## 工作流程

### Step 0 — 确认输入目录、目标金额与抬头规则

先确认：

- 输入目录路径（支持多个，用逗号分隔）
- 目标金额（例如 3000）
- 用户是否指定购买方抬头
- 默认操作流程是“扫描汇总 → 预览组合 → 用户确认 → 移动选中发票”；用户明确要求保留源文件时才改为复制

### Step 1 — 扫描目录（脚本，无 LLM）

```bash
python3 {skill_dir}/scripts/invoice_bundle.py scan --inputs <dir>[,<dir> ...] [--title <购买方抬头>]
```

输出 JSON 包含：

- 解析出的发票明细（发票号、价税合计、路径）
- 目录发票总额
- 重复发票号及对应文件
- 无法解析的 PDF 文件列表
- 购买方抬头分类、各类张数与金额
- 指定 `--title` 时的匹配和不匹配明细

用户未指定抬头时，先按扫描结果自动分类。若存在多个抬头或无法识别抬头的发票，展示分类并请用户确认使用规则；不要静默混用。

### Step 2 — 计算最优组合（脚本，无 LLM）

```bash
python3 {skill_dir}/scripts/invoice_bundle.py bundle --target <金额> --inputs <dir>[,<dir> ...] [--title <购买方抬头>]
```

组合规则：

- 总额 **不低于**目标金额
- 优先选择**超出金额最小**的组合
- 超出金额相同时，优先选择**张数最少**的组合
- 发票唯一性以**发票号**为准；重复发票号只保留首次出现的文件，其余计入重复列表
- 指定 `--title` 时，仅匹配该抬头的发票参与组合
- 未指定抬头且扫描出多个抬头或未知抬头时，脚本要求先确认；用户明确允许混用后才可使用 `--allow-mixed-titles`

默认只输出组合方案，**不改动任何文件**。

### Step 3 — 用户确认后移动

```bash
python3 {skill_dir}/scripts/invoice_bundle.py bundle --target <金额> --inputs <dir>[,<dir> ...] --output-root <dir> --apply [--title <购买方抬头>]
```

- `--apply` 默认使用 `move`，把选中发票移出可用目录，使原目录只保留未使用发票
- `--mode copy` 仅在用户明确要求保留选中源文件时使用
- 结果目录命名固定为 `YYYY-MM-DD_{预期金额}元_{张数}张`，例如 `2026-07-14_2000元_10张`
- 目录名金额取用户输入的目标金额，不取实际选中总额；实际总额继续写入脚本输出和交付说明
- 同名结果目录已存在时追加 `_1`、`_2`，不覆盖既有目录
- 执行后会再次扫描结果目录并校验合计金额，不一致时输出 `verify_ok: false`

### Step 4 — 交付与说明

向用户汇报：

- 扫描到的发票总数、总额、重复情况
- 是否找到满足目标的组合；选中发票张数、合计金额、超出金额
- 结果目录路径（若执行了 apply）
- 购买方抬头分类或指定抬头的匹配结果
- 无法解析的文件清单，提醒用户手工处理

## 行为边界

- **执行分两阶段**：先扫描和预览，用户确认组合后才执行 `--apply`；确认后的默认操作是移动。
- **抬头不静默混用**：用户未指定抬头时自动分类；存在多个分类或未知抬头时必须先确认规则。
- **测试和验证一律使用复制出来的临时样本**，不要直接操作用户的原始发票目录。
- **发票唯一性以发票号为准**，不以文件名为准。
- **不做 OCR**：只支持文本可提取的 PDF 发票。无法提取文本的扫描件会被报告为无法解析，不会静默跳过。
- **不删除用户文件**：清理旧目录、删除 `.DS_Store` 等操作不纳入默认能力。
- **已有报销目录里的票如果仍存在，重新拼单时视为可继续使用**，除非用户明确排除该目录。
- 组合默认规则为 `总额 >= 目标金额`，优先超出金额最小，金额相同再优先张数少。如用户有其他偏好（例如严格等于、允许略低），先确认再调整。

## 输出约定

- 脚本输出为 JSON，便于后续步骤读取和校验。
- 向用户展示时使用中文，结构清晰：扫描结果 → 组合结果 → 执行结果 → 待确认/异常项。
- 涉及路径时同时给出绝对路径，方便用户核对。
