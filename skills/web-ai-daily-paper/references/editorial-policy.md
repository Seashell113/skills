# 编辑与准入策略

## 编辑目标

早报是行业信息输入。不要把相关度收窄成“是否立刻影响当前项目”：行业重要性高或工作相关度高，满足任一项即可进入候选。

事实可信度是硬门槛；重要性、新闻性和栏目可以分级。A级不足时可补 B 级动态，不能补未核验消息。

## 主题范围

默认覆盖：

- AI 模型、AI 产品、AI 编程工具和 Agent 基础设施。
- Web 平台、浏览器、标准、新 API 和兼容性变化。
- React、Vue、Angular、Svelte、Next.js、Nuxt、Astro 等框架。
- Node.js、Deno、Bun、TypeScript、Vite、npm 和工程化生态。
- 开发者供应链、安全漏洞和重要事故。
- AI/Web 行业的重大融资、并购、政策、公司战略和基础设施事件。
- 有明确信号的新兴前端框架、工具与流行库。

普通营销活动、小规模融资、无产品化路径的纯论文、个人爆料和重复转载默认排除。

## 双轴判断

为候选分别判断：

- `industry_significance`：事件规模、跨来源覆盖、头部主体、生态影响、政策或安全影响。
- `work_relevance`：是否影响研发工具、技术选型、Web 能力、兼容性、工程效率或安全。

任一轴高即可成为 A 级候选。高热度由事件规模、来源权威和跨信源覆盖共同判断，不能直接等同于单平台点赞或热榜。

重大官方发布即使暂时只有一个一手来源，也可视为高确定性事件；热门传闻即使传播广，也必须通过事实证据门槛。

## 分级与栏目

### 今日重点

A级事件。典型情形：

- 重大模型、产品、AI 编程工具或平台能力发布。
- Web 平台、主流框架、运行时或工程化工具重大版本。
- 直接影响开发环境的安全事件。
- 影响行业格局的监管、并购、基础设施或头部公司战略。

### 补充动态

B级事件。事实可靠且近期有效，但影响范围较小，例如小范围功能上线、次要版本、局部生态变化。A级不足时用于补充正常信息量。

### 前端视野

每期最多 1-2 条，可计入 Web/前端覆盖和最低 5 条。候选需同时满足：

- 能明确说明新能力或解决的问题。
- 项目、规范或实现可访问。
- 维护活跃、文档基本完整。
- 至少有发布、采用、生态讨论或多个独立来源等信号之一。

单纯 GitHub Trending、营销软文、换皮项目和无维护迹象的仓库不收录。已介绍过的项目只有重大版本或明显采用变化才再次出现。

### 延伸阅读

事实新闻不足时最多补 2 条近期高质量技术解析、报告或实践文章。必须单独成栏，并说明其阅读价值；不能把文章发布日期包装成事件发生日期。

## 数量和覆盖

- 正常至少 5 条，通常 5-8 条。
- A级事件不因常规上限被排除；新闻密集日可扩展到约 12 条。
- 正常早报目标至少 2 条 Web/前端内容，“前端视野”可计入。
- 覆盖是软目标。没有合格内容时不得强行满足配比。
- 若 A/B 级不足，先补前端视野，再补最多 2 条延伸阅读。

## 时间窗口

- 普通新闻：从上次成功运行时间开始，最长回看 96 小时。
- 周一：自然覆盖周末，不固定截断为 48 小时。
- 未报过的 A 级重大事件：允许回看 7 天，标明实际发生日期和延迟纳入原因。
- 延伸阅读：最近 7 天。
- 同一事件只有出现新 milestone 才能再次报道。

## 事实与关注理由

每条分为：

1. `fact_summary`：发生了什么，只能使用 claim 证据。
2. `attention_reason`：为什么值得知道，可说明行业意义、采用信号或潜在影响。

关注理由可以是编辑推断，但要克制并体现不确定性。避免“必将”“彻底改变”“行业拐点”等无法证明的结论。

## 排序

通常按以下顺序排列：

1. 开发环境和供应链安全。
2. 头部 AI 编程工具、模型和平台重大变化。
3. Web 平台、框架、运行时、工程化更新。
4. 高信号前端视野。
5. 重大政策、并购和商业事件。
6. B级补充动态与延伸阅读。

同级内综合事件发生时间、行业重要性、工作相关度和证据强度排序，不机械套权重总分。
